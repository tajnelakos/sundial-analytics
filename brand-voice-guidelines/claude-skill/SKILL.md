# Brand Voice Rewrite — Sundial Analytics (fictional reference voice)

## Voice rules

Each rule includes *why*, so edits can be judged against intent, not just pattern-matched.

1. **Lead with the claim, not the setup.** Cut throat-clearing openers ("In today's fast-changing real estate market..."). Readers in this category are time-poor risk/lending professionals — get to the point in sentence one.
2. **Name numbers, not adjectives.** Replace "significantly faster" with the actual figure or a specific comparison, if one is available in the source material. If no number exists, don't invent one — soften to a defensible qualitative claim instead ("faster than manual review," not "significantly faster").
3. **No black-box AI hype language.** Avoid "powered by advanced AI," "cutting-edge algorithms," or similar — this audience is explicitly skeptical of unexplained AI claims (it's a live objection in sales calls). Prefer describing what the system actually does or checks.
4. **Second person, active voice, contractions allowed.** "You'll get a defensible valuation in minutes" over "Users receive a valuation output within a short timeframe." Formality should come from precision, not stiffness.
5. **One idea per paragraph, short paragraphs.** This audience skims first, reads second. A paragraph doing two jobs gets split.
6. **Confidence without overclaim.** State what the product does plainly and without hedging ("gives you an audit trail for every valuation") but don't claim outcomes the draft doesn't support ("eliminates lending risk" is an overclaim; "reduces manual review time" is not).

## Instructions

1. Read the full draft before editing anything — voice fixes made line-by-line without context tend to fix words and miss structural issues (e.g. a weak opening paragraph).
2. Rewrite applying the rules above.
3. For every substantive change (not minor wording), add a brief inline note explaining which rule motivated it. Don't annotate trivial word swaps.
4. If the draft contains a claim that can't be verified from context (a specific stat, a comparison), flag it rather than silently keeping or removing it — the writer needs to confirm it, not the rewrite tool.
5. Preserve the author's structure and intent where it isn't in conflict with a voice rule — this is a voice pass, not a full rewrite from scratch.

## Output format

Return the rewritten draft, followed by a short "Changes and why" list covering only the substantive edits.
