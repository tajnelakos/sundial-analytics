# Blog Post Builder

## The problem

Most B2B blog content is generic SEO-bait wearing a thought-leadership costume — a "how-to" post engineered to rank for a keyword, with no real argument underneath it. The fix isn't a better content template; it's requiring an actual, specific claim before drafting starts, the same way this repo's other skills require a real trigger, brief, or CRM record instead of a plausible-sounding invented one.

## The approach

Takes one of [`positioning.md`](../../knowledge-base/positioning.md)'s points of view, or a real finding from [`win-loss-analysis`](../../knowledge-base/win-loss-analysis), [`competitor-monitoring`](../../sales-tools/competitor-monitoring), or [`sales-call-analysis`](../../knowledge-base/sales-call-analysis), and builds a post around that one argument — SEO mechanics (keywords, meta description, title tag) applied after the real claim exists, not instead of one. Also handles a nuance the generic version of this skill wouldn't: internal sales intelligence (a named prospect's call, a named competitor) has to be generalized before it appears in public content, even though this repo names both freely in its internal-facing folders.

## Files

- [`skill.md`](./skill.md) — the Claude Skill definition
- [`example.md`](./example.md) — a post built from `positioning.md`'s "AI-powered isn't a differentiator" argument, illustrated with a generalized version of a real call and win-loss finding already in this repo

## Current limitations

Only one worked example exists so far, built for the Head of Credit Risk persona specifically. The other two `positioning.md` points of view, and other personas' content preferences, haven't been built out yet.
